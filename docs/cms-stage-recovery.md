# Conservative CMS staging recovery

M5t, 8 November 2026; private CMS baseline cdd97c5 / homepage 9734df7.
Public runtime, staging/candidate/Pages workflows, tools and dependencies are
unchanged. This repository receives documentation and mirrored diagrams only.

The Owner may retire an acknowledged exact first staging run after stable trusted
metadata proves completed failure or missing/expired upload. Fixed GETs repeat
run identity/state/code/time and artifact identity; prior uploaded proof binds
the known artifact. SQL repeats current Owner/source/candidate/proof/target and
prepared accepted-run checks before atomically retaining immutable retirement
and audit. No network work holds SQL locks. Private migration 00028 is required
only in the CMS; status projects retired without altering original history.

The lifetime limit stays three admissions per release. Retired/rejected and
prior-candidate requests still count. A fresh UUID needs its own later explicit
confirmation; recovery performs no dispatch, cancellation, rerun or deletion.
Old output/proofs cannot become current again; original records remain retained.

Unknown/lost acknowledgements remain blocked. An expired lease or unverified/
live/rerun/usable state never proves safe eligibility. No uncertain-run discovery
or binding is implemented. Stable reads are point-in-time provider evidence, not
atomic network revocation; trusted administrator/runner/provider compromise and
direct GitHub dispatch bypass remain limits. Hosted staging stays off by default;
no hosted settings, credentials or actions were used.

Next gates: trustworthy unknown-run reconciliation, protected exact deployment,
deployed-output proof and atomic destination completion. See [native diagrams](diagrams/cms-stage-recovery.drawio)
and [executed evidence](security/cms-stage-recovery.md). This is not publication.
